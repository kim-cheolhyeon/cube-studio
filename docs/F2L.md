# F2L · FR 페어 41개

## 범위와 학습 방향

십자가와 다른 세 F2L 슬롯이 맞은 상태에서 앞·오른쪽 FR 슬롯 한 쌍을 넣는 기본 연습입니다. U 노랑, D 흰색, F 초록, R 주황을 기준으로 합니다.

색칠 규칙은 기존 JSON 버전 3과 같습니다.

- protected: 흰 십자가 전체, FR 이외의 완성한 세 슬롯, 중앙 여섯 칸. 총 29칸.
- focus: 목표 흰색·초록색·주황색 코너 세 칸과 초록색·주황색 엣지 두 칸. 총 5칸.
- 기타: 검정. 실제 색은 state에 유지합니다.

## 목록

목록은 categoryPath 배열로 아래 계층을 표시합니다. 완성 상태는 포함하지 않습니다. 기존 케이스 ID와 번호는 유지합니다.

1. 두 조각 모두 위층
   - 바닥 면이 위를 보는 경우: 8개
   - 바닥 면이 위를 보지 않는 경우
     - 위의 두 면이 같은 색: 8개
     - 위의 두 면이 다른 색: 8개
2. 코너가 슬롯 안
   - 코너가 정방향: 2개
   - 코너가 다른 방향: 4개
3. 엣지가 슬롯 안
   - 엣지가 정방향: 3개
   - 엣지가 다른 방향: 3개
4. 둘 다 슬롯 안
   - 코너만 정방향: 1개
   - 엣지만 정방향: 2개
   - 둘 다 다른 방향: 2개

바닥 면은 목표 코너의 D색(현재 학습 방향에서는 흰색) 스티커입니다. 위의 두 면은 목표 코너·엣지에서 U를 향한 스티커 두 개입니다. 슬롯 안 정방향은 해당 조각의 모든 스티커가 각 면의 중앙색과 일치하는 상태입니다.

| 묶음 | 케이스 수 |
|---|---:|
| 두 조각 모두 윗층 | 24 |
| 코너가 슬롯 안 | 6 |
| 엣지가 슬롯 안 | 6 |
| 두 조각 모두 슬롯 안 | 5 |
| 합계 | 41 |

윗면 회전으로 같은 케이스가 되는 배치를 묶었습니다. 코너가 윗층이면 UFR 기준, 코너가 아래 있고 엣지가 윗층이면 UF 기준으로 보여줍니다. 케이스 이름에는 코너 흰색과 엣지 초록색의 방향도 표시합니다.

**케이스 번호는 앱 내부 분류 번호입니다. 다른 공식집의 F2L 번호와 대응한다고 가정하지 마세요.**

## 공식의 성격

### A·B·C·D 연결 학습

기본 케이스 8개를 목록 맨 위에서 따로 연습합니다.

화면에서는 A·B·C·D 대신 다음 이름을 사용합니다. 내부 basicCase.kind는 연결 관계를 위해 유지하며 basicCase.name에 표시 이름을 저장합니다.

- A: 완성 페어 — 코너와 엣지가 결합된 상태.
- B: 같은 윗색 — 분리된 코너와 엣지의 위쪽 스티커가 같은 색.
- C: 다른 윗색 — 분리된 코너와 엣지의 위쪽 스티커가 다른 색.
- D: 바닥색 위 — 코너의 바닥색 스티커가 위를 향한 상태.

같은 윗색·다른 윗색은 바닥색이 옆을 향한 기본형에 사용합니다. 바닥색이 위를 보면 바닥색 위로 구분합니다. 완성 페어는 결합 여부로 먼저 구분합니다.

| 기본형 | 오른쪽 | 왼쪽 | 풀이 |
|---|---|---|---|
| A: 위층의 완성 페어 | 03 | 04 | 삽입 |
| B | 16 | 14 | A로 페어 만들기까지 |
| C | 01 | 02 | A로 페어 만들기까지 |
| D: 바닥색이 위를 보는 기본형 | 05 | 06 | A로 페어 만들기까지 |

좌우는 서로 대칭인 배치를 구분하는 이름입니다. B 오른쪽에서 A 왼쪽으로 연결되는 등 연결 대상의 이름은 구간 제목에 표시합니다.

나머지 33개는 기존 판별 계층을 유지하며 A·B·C·D 중 하나로 유도합니다. A로 직접 연결되는 경우에는 B·C를 거치지 않습니다. 완성 상태를 중간 경유점으로 사용하지 않습니다.

일반 33개 케이스는 A·B·C·D에 도달하면 재생이 끝납니다. B·C·D 기본형 6개는 A에 도달하면 끝납니다. 이후 기본형의 공식은 현재 JSON 해법에 포함하지 않으므로 다시 재생해도 삽입으로 이어지지 않습니다. A 기본형 2개만 삽입까지 수행합니다. solutions[0].algorithm과 segments에는 해당 한 구간만 기록합니다. 이전 수·다음 수는 한 수씩 이동하며 문제 상태로 초기화하면 출발 케이스로 돌아갑니다.

도착 배치에서 목표 페어의 5개 스티커가 지정한 A·B·C·D 케이스와 일치하는지, 보존할 29칸이 원래 상태인지 검증합니다. A 기본형에서는 목표 페어도 완성됩니다. 중간 회전 중에는 슬롯을 열 수 있습니다.

윗면 회전과 오른쪽·앞쪽 슬롯을 열고 닫는 동작을 조합해 앱의 회전 모델에서 계산했습니다. 빠른 실전 기록용 최단 공식 모음은 아닙니다. 각 케이스의 공식은 지정한 기본형에 도달하고 십자가와 나머지 세 슬롯을 복원하도록 검증합니다.

시작 상태는 합법적 회전으로 생성했습니다. 150개 목표 페어 배치에서 윗면 회전 중복을 묶고 이미 완성된 경우를 제외해 41개를 만들었습니다.

기본 F2L의 범위와 분류는 [CubingApp F2L](https://cubingapp.com/algorithms/F2L)을 참고했습니다. 해당 사이트의 그림이나 전체 공식 목록을 복사한 것이 아니라 상태와 연결 공식을 직접 계산했습니다.
