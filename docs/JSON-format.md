# Cube Studio JSON · 버전 3

## 케이스는 독립된 학습 단위

단계 순서가 없어도 케이스를 만들 수 있습니다. 각 케이스에서 다음을 명시합니다.

- 시작 전제: 이 연습이 어떤 상태에서 시작한다고 가정하는가.
- 보존: 공식이 끝난 뒤에도 유지되어야 하는 부분.
- 목표: 이번 공식으로 위치나 방향을 맞출 조각.

보존은 이전 단계의 결과일 수도 있지만, 반드시 이전 단계가 있어야 하는 것은 아닙니다. 초급 층별 해법과 F2L 단독 연습 모두 이 규칙을 사용합니다.

## 색칠과 검정의 정의

| 구분 | 정의 | 현재 JSON 필드 | 표시 |
|---|---|---|---|
| 보존 | 이 케이스의 전제로 맞춰져 있고, 공식 후에도 유지해야 하는 스티커 | protected = true | 실제 색 |
| 목표 | 이번 케이스에서 맞출 조각의 스티커 | focus = true | 실제 색 |
| 기타 | 보존·목표로 지정하지 않은 스티커 | 둘 다 false | 검정 |
| 중앙 | 면 방향을 읽는 여섯 기준 칸 | 제공 데이터는 protected = true | 실제 색 |

이 문서는 현재 구현된 protected와 focus를 사용합니다. 별도의 roles 필드로 옮긴 상태는 아닙니다. 보존과 목표가 겹쳐도 색칠 결과는 동일하지만, 새 케이스에서는 목적에 맞게 구분해 지정하세요.

### 필수 규칙

1. 표시 역할은 케이스 작성자가 정합니다. 현재 중앙색과 우연히 같은지로 자동 결정하지 않습니다.
2. 보존은 이 케이스에서 유지해야 하는 범위를 빠짐없이 포함합니다.
3. 목표 엣지는 스티커 두 칸, 목표 코너는 세 칸을 모두 표시합니다. 두 조각의 페어라면 다섯 칸입니다.
4. 제공하는 새 케이스는 protected와 focus를 여섯 면 각각 boolean 9개씩 명시합니다. 보존 대상이 없으면 중앙을 제외한 protected를 false로 둡니다.
5. 각 표시 역할은 회전하는 스티커를 따라갑니다. 중간에 흐트러졌다고 검정으로 바꾸거나 우연히 맞았다고 색칠하지 않습니다.
6. 실제 색은 state에 모두 보존합니다. 검정 표시를 위해 state를 K로 덮어쓰지 않습니다.
7. 보존은 매 순간 고정되어야 한다는 뜻이 아닙니다. 공식 도중 움직일 수 있고, 공식이 끝나면 케이스의 보존 조건을 다시 충족해야 합니다.

현재 렌더링은 protected 또는 focus가 true이면 실제 색, 둘 다 false이면 검정입니다. 제공 자료의 여섯 중앙은 항상 protected에 포함합니다. 체크를 끄면 모든 실제 색이 보이고, 노션 카드에는 현재 표시 설정이 반영됩니다.

## 독립적인 F2L 예시

### 십자가를 유지하며 FR 페어 삽입

- 시작 전제: 십자가가 완성되어 있고 삽입할 코너·엣지가 지정된 위치에 있음.
- 보존: 십자가의 모든 스티커와, 유지하기로 한 다른 완성 F2L 슬롯의 모든 스티커.
- 목표: 이번 코너 세 칸과 엣지 두 칸.
- 기타: 아직 맞추지 않은 다른 조각. 검정 표시.

다른 슬롯이 맞춰져 있다고 가정하지 않는 케이스라면, 그 슬롯을 보존 대상으로 임의 추가하지 않습니다.

### 십자가 없이 페어 만들기만 연습

- 시작 전제: 연습할 코너와 엣지가 지정된 위치에 있음.
- 보존: 필수 유지 조각 없음. 중앙 여섯 칸만 방향 기준으로 표시.
- 목표: 해당 코너·엣지의 다섯 스티커.
- 기타: 나머지 조각은 검정 표시.

## 현재 저장 구조

- formatVersion: 3.
- displayRule: protected-and-current-target.
- cases: 케이스 목록.
- id, name: 고유 ID와 이름.
- category, tags: 분류와 태그. category는 학습 순서를 강제하지 않습니다.
- description: 시작 전제와 이번 목표를 설명합니다.
- state: F, B, R, L, U, D 면에 실제 색 9개씩.
- protected, focus: 같은 여섯 면에 boolean 9개씩.
- solutions: name, algorithm, note를 가진 해법 목록. note에는 보존 조건과 수행 후 목표를 설명합니다.

아래처럼 각 면에 9개 값을 기록합니다. 이는 한 면의 필드 예시이며 완전한 케이스 파일은 아닙니다.

```json
{
  "state": {"F": ["G", "G", "O", "G", "G", "Y", "G", "G", "G"]},
  "protected": {"F": [false, false, false, false, true, false, true, true, true]},
  "focus": {"F": [false, false, true, false, false, true, false, false, false]}
}
```

프로그램 검사는 배열 형식과 공식 문법 등을 확인합니다. 시작 전제의 타당성, 보존 조건의 복원, 목표의 달성은 케이스 추가 시 별도로 검증해야 합니다. 일반 파일에 이 세 의미 검증을 자동 수행하는 기능은 아직 없습니다.

## 색과 좌표

W 흰색, Y 노랑, R 빨강, O 주황, G 초록, B 파랑. K는 실제 색을 기록하지 않은 검정 칸을 직접 입력하는 호환 코드입니다. 학습 데이터에는 원래 색을 저장하고 표시 필드로 가립니다.

면 배열은 바깥에서 바라본 왼쪽 위부터 가로로 9칸입니다. 옆면의 위는 U, U의 위는 B, D의 위는 F 방향이며 U와 D 배열의 왼쪽은 L 방향입니다.

기본 완성 방향: F 빨강 / R 노랑 / U 파랑 / B 주황 / L 흰색 / D 초록.
초급 케이스의 학습 방향: U 노랑 / D 흰색 / F 초록 / R 주황 / B 파랑 / L 빨강. 같은 큐브를 전체 회전한 방향입니다.

## 파일 위치와 수정

- 원본 데이터: [data/beginner/cases.json](../data/beginner/cases.json)
- F2L 원본 데이터: [data/f2l/cases.json](../data/f2l/cases.json)
- 자동 불러오기용 생성 파일: 각 컬렉션 폴더의 cases.bundle.js
- 생성 명령: 프로젝트 폴더에서 node tools/build-case-bundle.cjs

JSON을 수정한 뒤 생성 명령을 실행하고 화면을 새로고침합니다. 생성 파일을 직접 편집하지 않습니다. 로컬 파일로 열 때도 자동 불러오기가 되도록 일반 스크립트 방식의 생성 파일을 유지합니다.

이전 버전과의 호환을 위해 protected가 없으면 전체 실제 색을 표시합니다. 새 자료에는 역할을 명시하여 이 기본값에 의존하지 마세요.

## Export

Export에서 이미지로 저장(PNG), JSON으로 저장, 이미지 복사를 제공합니다. JSON 한 파일에는 현재 상태의 케이스 한 개가 담깁니다. 실제 색과 현재 위치의 protected·focus를 보존합니다. 화면에서 검정 표시를 꺼도 역할 데이터는 유지됩니다.

공식을 입력하지 않으면 solutions는 빈 배열입니다. 이 상태는 불러올 수 있지만 재생할 해법은 없습니다. 공식을 입력하면 문법을 확인한 뒤 solutions에 기록합니다. 공식이 현재 상태를 해결하는지는 별도 검증해야 합니다.

학습 목록의 최상위는 컬렉션(초급 해법, F2L), 그 아래는 각 케이스의 category에 따른 묶음입니다. 컬렉션 이름은 앱이 데이터를 합칠 때 지정합니다. 폴더나 목록 순서는 protected의 전제 조건을 결정하지 않습니다. 각 케이스가 독립적으로 보존할 조각과 목표 조각을 명시해야 합니다. F2L 기준은 [F2L.md](F2L.md)를 참고하세요.
